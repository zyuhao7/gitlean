# Day 28：常见协作规范

## 学习目标

了解团队项目中的基础协作规则。

## 常见规范

- `main` 分支保持稳定。
- 新功能从 `feature/*` 分支开发。
- 修复线上问题可以使用 `hotfix/*` 分支。
- 合并前先拉取最新代码。
- 不提交密钥、密码、`.env` 等敏感文件。

## 分支命名示例

```text
feature/user-login
fix/readme-typo
hotfix/payment-error
docs/git-guide
```

## 今日练习

1. 创建一个符合规范的分支。
2. 提交一次小修改。
3. 推送这个分支。

## 检查点

你应该知道：规范的目标是减少协作成本，而不是增加形式感。
